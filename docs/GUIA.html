Seu DSB Manager.

HTML, CSS e JavaScript puro, com autenticação e banco de dados no Supabase. Guia da primeira configuração.

Estado da entrega: interface e integração implementadas. O painel foi preparado para uso com login real. A tela pública não oferece demonstração, cadastro ou configuração técnica. Login, recuperação de senha e persistência dependem da configuração do seu projeto Supabase.

1. Abrir no VS Code

  1. Extraia o ZIP inteiro em uma pasta.
  2. No VS Code, use Arquivo → Abrir pasta e escolha DSB-Manager.
  3. Com a extensão Live Server, clique com o botão direito em index.html → Open with Live Server.
  4. Configure o Supabase seguindo as etapas abaixo e entre com uma conta autorizada.

Não precisa instalar Node nem executar npm para usar o projeto. Use um servidor HTTP como o Live Server, em vez de abrir o HTML com file://.

2. Criar as tabelas e permissões

  1. Abra um projeto Supabase sob seu controle. Recomenda-se um projeto separado dos seus outros produtos.
  2. Abra SQL Editor → New query.
  3. Copie o conteúdo de schema.sql e execute.
  4. As tabelas criadas começam com dsb_. O script não altera tabelas de outros sistemas.

3. Criar o primeiro administrador

  1. Em Authentication → Users → Add user → Create new user, crie a sua conta com e-mail válido e senha forte. Confirme a conta pelo painel quando apropriado.
  2. No SQL Editor, execute o comando abaixo, substituindo o e-mail pelo da conta que acabou de criar:
insert into public.dsb_members(user_id,name,email,role)
select id,'Vitor',lower(email),'admin'
from auth.users
where lower(email)=lower('SEU_EMAIL_AQUI')
on conflict(user_id) do update set role='admin';

Confira em Table Editor → dsb_members que seu usuário aparece. Se nenhuma linha foi criada, confira o e-mail exato. Não há senha padrão nem registro público de administradores.

4. Conectar o painel

No Supabase, copie a Project URL e a chave publishable (a chave legada anon também é aceita). Elas ficam nas configurações do projeto / API.

Edite supabase/config.js:

window.DSB_CONFIG = {
  supabaseUrl: 'https://SEU-PROJETO.supabase.co',
  supabaseKey: 'SUA_CHAVE_PUBLICA'
};

A URL real deve usar o identificador do projeto, em letras minúsculas. Esses dois valores são públicos e podem estar no frontend. Nunca coloque a service_role, sb_secret_, senha do banco ou senha pessoal nesse arquivo.

A configuração técnica não aparece na tela pública. Preencha o arquivo antes de publicar o site.

5. Recuperação de senha e acesso

  1. Em Authentication → URL Configuration, configure a Site URL com a URL final do painel.
  2. Adicione a URL final exata (incluindo a barra final, se usada) à lista de Redirect URLs. Para desenvolvimento, adicione também seu endereço do Live Server, como http://127.0.0.1:5500/.
  3. Configure o envio de e-mails do Supabase com SMTP próprio para uso em produção. O remetente de teste pode ter limites e restrições de destinatários.
  4. Desative novas inscrições públicas nas configurações de Auth se não forem utilizadas. Mesmo uma conta criada diretamente não terá acesso sem ser autorizada em dsb_members.

Manter conectado: marcado, guarda o token de sessão no localStorage; desmarcado, usa sessionStorage (normalmente até fechar a aba, conforme o comportamento do navegador). A senha não é guardada pelo aplicativo. Use apenas em dispositivos de confiança. O botão Sair encerra a sessão local no Supabase e limpa o token.

6. Adicionar Leonardo ou outra pessoa

  1. Crie a conta em Authentication → Users, sem compartilhar a conta do administrador.
  2. Entre no DSB Manager como administrador.
  3. Abra Equipe → Autorizar acesso.
  4. Preencha o mesmo e-mail, o nome e a função. O painel não envia convites automáticos.
  5. Se houver uma restrição adicional de compartilhamento do link de hospedagem, conceda acesso ao site ou hospede os arquivos no provedor escolhido. A versão Sites entregue inicialmente é privada para o proprietário.

7. Usar no dia a dia

  • Clientes: contatos, status comercial e observações.
  • Projetos: cliente vinculado, prazo, responsável, valor, etapa e progresso.
  • Tarefas: quadro de etapas, prioridades, responsáveis e conclusão.
  • Financeiro: receitas e despesas, vencimentos, confirmação de pagamento e exportação CSV.
  • Agenda: compromissos, horários de Brasília, locais e duração.
  • Visão geral: indicadores calculados com os registros, fluxo de caixa e próximas tarefas.
  • Busca: Ctrl K ou a busca no cabeçalho.
  • Exportação: configurações → JSON. Esse arquivo é uma cópia para consulta; não há importação automática.

O valor de um projeto não gera receita automaticamente. Registre parcelas em Financeiro e confirme o pagamento quando recebido. Os totais pagos usam a data do pagamento; pendências usam o vencimento. O saldo mostrado é do mês, sem saldo inicial bancário. O gráfico exibe os seis meses até o mês selecionado.

Os registros são salvos ao confirmar o formulário. O botão de atualizar carrega as mudanças feitas por outros membros. Não há atualização em tempo real. Se duas pessoas editarem o mesmo registro, a versão impede que uma alteração sobrescreva silenciosamente a outra; atualize e revise o formulário.

8. Publicar em outra hospedagem

Publique o conteúdo da pasta DSB-Manager em um serviço para sites estáticos, como o que você já utiliza. O index.html deve ficar na raiz pública. Use HTTPS e atualize as URLs de recuperação no Supabase. Nenhum servidor Java é necessário: este projeto usa JavaScript no navegador.

A biblioteca Supabase está incluída em supabase/supabase.js; o login não depende de um CDN para carregar o SDK. As fontes do Google têm alternativas locais se estiverem indisponíveis.

9. Verificações antes de inserir dados reais

  1. Entre com o administrador e crie um cliente de teste. Recarregue: o registro deve permanecer.
  2. Entre com o segundo usuário em outro navegador: ele deve ver o mesmo cliente.
  3. Teste uma conta sem autorização: ela não deve conseguir ler registros, mesmo com login válido.
  4. Teste o colaborador: criar/editar deve funcionar; excluir e alterar a equipe devem ser negados pelo banco.
  5. Confira a recuperação de senha e as duas opções de permanência de sessão.

As políticas RLS são aplicadas pelo banco. Revogar um membro bloqueia futuras requisições; não apaga informações que ele já tenha visto ou exportado. Mantenha backups do Supabase e restrinja quem é administrador.
